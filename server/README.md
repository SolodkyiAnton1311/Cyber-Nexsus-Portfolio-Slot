# Demo Slot API

Небольшой сервер для демо-слота 5×3 на Node.js + TypeScript. Это учебная демонстрация, а не production-система: здесь нет пользователей, базы данных, сохранённого баланса, платежей или реальных ставок. Клиент передаёт ставку на линию; поле, выигрыши и бонусные спины рассчитываются сервером.

## Требования

- Node.js `>=18.12.0` и npm (Node.js 22 LTS рекомендован для развёртывания).

## Запуск локально

```powershell
Copy-Item .env.example .env
npm install
npm run dev
```

Сервер стартует на `http://localhost:3000`. Для компиляции TypeScript выполни `npm run build`, production запуск — `npm start`, тесты — `npm test`. Production запускает собранный JavaScript из `dist/`, поэтому нативный запуск TypeScript в Node не требуется.

Разрешённый origin клиента задаётся в `.env` через `CLIENT_ORIGINS` (несколько origin можно перечислить через запятую). Для локального Vite уже указан `http://localhost:8080`. Не коммить `.env`.

## API

### `GET /healthz`

Проверка доступности:

```json
{ "status": "ok" }
```

### `GET /api/config`

Возвращает размеры поля, список символов как числовые ID `0`–`12`, все paylines, reel strips с числовыми ID, лимиты ставки, paytable и правила Scatter/Free Games. ID по порядку: Wild, H1, H2, M1, M2, M3, L1–L6, Scatter. Символьные значения в API — только числа; клиент сам сопоставляет ID со спрайтами.

### `POST /api/spin`

Запрос (ставка на одну линию):

```json
{ "bet": 25 }
```

Ответ содержит `roundId`, `bet` / `lineBet`, `totalBet`, платное поле `board`, `wins`, `baseGamePayout`, результаты автоматически рассчитанных `freeGameResults`, общую выплату `payout` и `net`. `board` — массив из 3 строк по 5 числовых ID символов из `/api/config`. Не передавайте поле или сумму выигрыша: сервер их не принимает от клиента.

Wager настраивается числовыми значениями из `/api/config`: ставка на линию — от `1` до `10000`, активны `10` линий, общий wager платного спина равен `bet × 10`. Если выпали Scatter, сервер рассчитывает все присуждённые Free Games в том же ответе: их выплаты входят в `payout`, но ставка не списывается. Каждая запись `freeGameResults` содержит своё поле и выплату; повторные бонусы в них отключены.

## Демонстрационные правила

- Поле 5×3; десять фиксированных paylines. Выигрыши считаются слева направо; за линию выплачивается только лучший результат.
- Пять независимых ordered reel strips по 100 стопов. Каждый содержит L1–L6 по 11, M1–M3 по 7, H1–H2 по 4, WW дважды и SC трижды. У каждой пары Scatter-стопов на кольцевом риле не менее 32 стопов между ними, поэтому одно окно не может показать два Scatter с одного рила.
- Числовой paytable индексируется по ID символа; значения в каждой строке соответствуют 3 / 4 / 5 совпадениям: H1–H2 — `184 / 612 / 2,447`; M1–M3 — `80 / 275 / 1,040`; L1–L6 — `31 / 110 / 427`. Множители применяются к ставке на линию.
- `WW` заменяет L/M/H, но не Scatter. Если линия начинается с Wild, выбирается лучший допустимый выигрыш; пять Wild оплачиваются как пять High.
- Scatter считается в любых из 15 видимых ячеек: 3 дают 5 Free Games, 4 дают 10, 5 дают 15. Free Games используют те же рилы, линии и line bet, но не списывают ставку и не запускают повторный бонус.
- Базовый RTP по модели — `92.9146%`; с ожидаемой стоимостью Free Games теоретический общий RTP — `96.0047%` (округлённо `96.00%`). RTP — долгосрочное математическое ожидание, не гарантия результата короткой серии.
- `net = общая выплата (paid + free games) - totalBet`; `totalBet = bet × 10`. Баланс не хранится и достаточность средств не проверяется.

## Подключение Vite-клиента

В конфигурации Vite можно проксировать `/api` и `/healthz` на `http://localhost:3000`; тогда клиент вызывает `fetch('/api/spin', ...)`. Вызов `/api/spin` должен быть заблокирован в интерфейсе на время запроса. Ответ содержит результаты Free Games сразу, поэтому клиент может показать их поочерёдно без хранения серверной сессии.

## Контейнер

```powershell
docker build -t demo-slot-api .
docker run --rm -p 3000:3000 --env-file .env demo-slot-api
```

Перед публичным размещением отдельно настройте HTTPS, реальные разрешённые origins, лимиты нагрузки, мониторинг и правила игры. Этот каркас не реализует аутентификацию и не предназначен для азартных игр на деньги.
